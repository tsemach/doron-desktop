# ASC-105 — Add user area in the backend — Roadmap

**Linear issue:** [ASC-105](https://linear.app/amicusx/issue/ASC-105/add-user-area-in-the-backend) — "Add user area in the backend"
**Date:** 2026-08-10 (last updated 2026-08-11)

ASC-105 describes a large architectural shift: moving primary business logic
and UI from the desktop-only Tauri app into a multi-tenant SaaS "user area"
hosted in `apps/backend`, with the desktop app becoming more of a
local-machine-access GUI. It's too large for one spec/plan/PR, so it was
broken into six independent sub-projects, in rough dependency order. Each
sub-project gets its own spec → plan → implementation → PR cycle.

## Sub-project 1 — Private-area shell & entry point

**Status: Ready for review** — PR [#158](https://github.com/tsemach/doron-desktop/pull/158) open against `master`, branch `tsemachmizrachi/asc-105-add-user-area-in-the-backend`. All 6 implementation tasks complete and individually reviewed clean; final whole-branch review passed after one fix-wave round; full backend suite green (132/132); `tsc --noEmit` and `pnpm build` clean.

Delivers: a logged-in user landing on `/` is redirected straight into a new
`/app` private workspace shell; anonymous visitors still see the existing
marketing homepage (moved to `/home`); the in-app logo links back to public
content without a redirect loop. Placeholder-only content — no real
dashboard, no case/document data.

Parked (not blocking, flagged for follow-up): `auth()` is called twice per
`/app` render with no request-level caching; the private shell currently
inherits the marketing site's footer.
