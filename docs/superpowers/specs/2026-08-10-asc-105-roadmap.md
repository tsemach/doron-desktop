# ASC-105 — Add user area in the backend — Roadmap

**Linear issue:** [ASC-105](https://linear.app/amicusx/issue/ASC-105/add-user-area-in-the-backend) — "Add user area in the backend"
**Date:** 2026-08-10 (last updated 2026-08-12)

ASC-105 describes a large architectural shift: moving primary business logic
and UI from the desktop-only Tauri app into a multi-tenant SaaS "user area"
hosted in `apps/backend`, with the desktop app becoming more of a
local-machine-access GUI. It's too large for one spec/plan/PR, so it was
broken into independent sub-projects, in rough dependency order, each
tracked as its own Linear sub-issue under ASC-105. Each sub-project gets its
own spec → plan → implementation → PR cycle. Sub-project 2.5 was inserted
after the fact, between 2 and 3: sub-project 2's PR grew large through many
rounds of follow-up polish, so further additions to the opening/dashboard
page continue on their own stacked branch/PR instead of piling onto #2's.

## Branch stacking

Sub-project 1's PR #158 is not yet merged to `master`, but sub-projects 2 and
6 build directly on the `/app` shell files it adds. Rather than blocking on
the merge, sub-project 2's work happens on a branch stacked on top of #1:
`tsemachmizrachi/asc-105-add-user-area-in-the-backend-pr-2`, forked from
`tsemachmizrachi/asc-105-add-user-area-in-the-backend` (not `master`).
Its eventual PR will target the sub-project-1 branch (or need a rebase onto
`master` once #158 merges) rather than `master` directly.

Sub-project 2.5 continues the same stack one level further: branch
`tsemachmizrachi/asc-105-add-user-area-in-the-backend-pr-2.5`, forked from
`...-pr-2` at the point sub-project 2 was marked ready for review. No
separate worktree is kept for it day-to-day — it's checked out into the
same `.worktrees/tsemachmizrachi/asc-105-add-user-area-in-the-backend-pr-2`
working directory as sub-project 2 (swap branches there with `git checkout`)
rather than maintaining a second worktree alongside it.

## Sub-project 1 — Private-area shell & entry point

**Status: Ready for review** — PR [#158](https://github.com/tsemach/doron-desktop/pull/158) open against `master`, branch `tsemachmizrachi/asc-105-add-user-area-in-the-backend`. All 6 implementation tasks complete and individually reviewed clean; final whole-branch review passed after one fix-wave round; full backend suite green (132/132); `tsc --noEmit` and `pnpm build` clean.

Delivers: a logged-in user landing on `/` is redirected straight into a new
`/app` private workspace shell; anonymous visitors still see the existing
marketing homepage (moved to `/home`); the in-app logo links back to public
content without a redirect loop. Placeholder-only content — no real
dashboard, no case/document data.

Parked (not blocking, flagged for follow-up): `auth()` is called twice per
`/app` render with no request-level caching; the private shell currently
inherits the marketing site's footer.

## Sub-project 2 — Opening/dashboard page

**Status: Ready for review** — PR [#159](https://github.com/tsemach/doron-desktop/pull/159) open against sub-project 1's branch (not `master` — branch-stacked, see above), branch `tsemachmizrachi/asc-105-add-user-area-in-the-backend-pr-2`. All 5 planned tasks complete and individually reviewed clean; final whole-branch review (opus) found 3 Important findings (server-locale/timezone timestamp formatting, an unmapped-icon runtime-crash risk, and low-legibility open/closed status pills), all fixed in one fix-wave round and re-review-verified; full backend suite green (132/132, no new test files — presentational/mocked content has no unit-test convention in this codebase); `tsc --noEmit` and `pnpm --filter backend build` clean; manually verified via a live browser walkthrough at desktop and mobile widths.

Delivers: replaces the sub-project-1 placeholder at `apps/backend/app/app/page.tsx` with a mocked, bird's-eye-view overview — a "Recent Cases" list (5 most recent, sorted by `updatedAt`), a 2×2 stat-tiles grid (emails/meetings/cases/tasks), and a notifications panel, in a two-column layout collapsing to one column below `lg`. Deliberately excludes app-wide nav tabs, chat, case actions, and urgency tags (left for later sub-projects); all content is static mock data with no dependency on sub-project #3's data-ownership decision.

Note: after the plan above landed, PR #159 kept growing through many
additional rounds of ad-hoc visual/UX iteration directly on the same branch
(a persistent topbar nav menu with coming-soon routes, "Open Cases" reworked
into collapsible "Open Activities" groups, a redesigned floating
notification bell, and several spacing/color passes) — none went through a
formal plan cycle, since each was a small, immediately-verified visual
tweak. That accumulation is exactly why sub-project 2.5 exists: further
dashboard changes continue on their own branch instead of this one.
